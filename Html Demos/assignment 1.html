the brief

The scenario

The Northstar Astronomy Club needs a single-page website to announce its events, publish its season schedule, and let visitors sign up. The club has handed you all of its text and data (see the Starter content appendix). Build the page from an empty file: write the HTML structure first, then a separate stylesheet to bring it to life.

This assignment assesses whether you can choose the right tag for the right job, separate structure from style, and lay content out responsively — the three habits both manuals were built around.

Read this first

You are graded on your own code, not on matching the demo pixel-for-pixel. Reasonable design choices are welcome. What must be correct is the semantics, the requirements checklist, and the responsiveness. Do not copy the finished tutorial file — build it yourself.

what this proves

Learning outcomes

On completing this assignment you should be able to:

  • Structure a web page with correct, semantic HTML5 (document skeleton, headings, lists, links, media, sectioning, tables, and forms).
  • Connect and organise an external stylesheet, and target elements precisely with selectors.
  • Control spacing and sizing with the box model, and theme a site with custom properties.
  • Lay out a page using Flexbox and CSS Grid, choosing the right tool for each region.
  • Make a layout responsive with mobile-first media queries and fluid units.
  • Apply restrained motion and meet basic accessibility standards.
part a

Part A — Structure it with HTML

Create index.html. Work top to bottom; each task lists the acceptance criteria you'll be checked against. The chapter tag on the right points to where it was taught.

A1 The document skeleton HTML · Ch.1

Set up a valid, mobile-ready document.

  • Include <!DOCTYPE html>, <html lang="en">, <head>, and <body>.
  • Add <meta charset>, the <meta name="viewport"> line, and a descriptive <title>.
  • Add a <meta name="description"> summarising the club.

A2 Header & navigation HTML · Ch.4, 6

Build a site header containing the club name and a navigation menu.

  • Wrap it in a <header> and use a <nav> for the menu.
  • Build the menu as a <ul> of <a> links.
  • Each link must jump to a section further down using an #id anchor (Events, Schedule, Join).

A3 Hero section HTML · Ch.2, 6

Create an intro banner that welcomes visitors.

  • Use a single <h1> for the page's main title.
  • Add the tagline and intro paragraph, with the meeting day in <strong>.
  • Include a call-to-action link to the join section.

A4 Events — a set of cards HTML · Ch.6

Present the four events as self-contained, repeatable units.

  • Group them inside a <main> and a titled <section> (one <h2>).
  • Make each event an <article> with its own <h3>, date, and description.
  • Justify your choice of <article> over <div> in a code comment.

A5 Schedule — a data table HTML · Ch.7

Turn the schedule data into a proper table.

  • Use <table> with <caption>, <thead>, and <tbody>.
  • Header cells are <th scope="col">; data cells are <td>.

A6 Join — a form HTML · Ch.8

Build the membership form so the club can collect sign-ups.

  • Wrap controls in a <form>. Every input has a <label> tied by for/id.
  • Include: a text name field, an email field, a <select> for experience, a <textarea>, a consent checkbox, and a submit <button>.
  • Mark the name and email required and give text fields a placeholder.

A7 Footer HTML · Ch.6

Close the page with a <footer> containing contact info (a mailto: link) and a copyright line.

part b

Part B — Style it with CSS

Create a separate styles.css and link it from the <head>. Style only with CSS — do not add inline style="" attributes (except none at all is the goal).

~50 marks · The Style Manual

B1 Connect, reset & base CSS · Ch.1, 3

  • Link the external stylesheet with <link rel="stylesheet">.
  • Add a reset that sets box-sizing: border-box and removes default margins.
  • Set base font-family, line-height, colour, and background on body.

B2 A variable-driven palette CSS · Ch.4

  • Define at least five custom properties on :root (colours + a radius).
  • Use var(...) everywhere those values appear — no hard-coded duplicates.
  • Give the hero a gradient background.

B3 Typography CSS · Ch.5

  • Load and apply at least one web font, with a generic fallback.
  • Set a clear type scale; remove underlines from nav links; control line-height and a heading's letter-spacing.

B4 The box & the cards CSS · Ch.2, 3

  • Centre the content with a max-width container and auto margins.
  • Style event cards with padding, border, radius, and a background — using class selectors.
  • Stripe the schedule table rows with :nth-child(even).

B5 Layout — Flexbox CSS · Ch.7

  • Make the header a flex row: logo left, nav pushed right (margin-left:auto).
  • Use flex to align the form fields and/or button row.

B6 Layout — Grid CSS · Ch.8

  • Lay the event cards out with display: grid and gap.
  • Explain in a comment why Grid (not Flexbox) suits the card area.

B7 Responsive CSS · Ch.9

  • Work mobile-first: cards stack in one column by default.
  • Add @media (min-width: …) rules so cards become 2 then 3 columns on wider screens.
  • Use a fluid unit somewhere meaningful (e.g. clamp() on the h1).

B8 Motion & polish CSS · Ch.10

  • Add a hover effect to the cards and/or button using transition + transform.
  • Provide a visible :focus state on links and the button (keyboard accessibility).
  • Respect @media (prefers-reduced-motion: reduce).
non-negotiables

Hard requirements

These are checked before marking the rest. Missing any will cap your grade.

01Two separate files: index.html and styles.css (external CSS only).
02Hand-written code. No frameworks (Bootstrap, Tailwind) and no CSS libraries.
03HTML passes the W3C validator with no errors.
04Exactly one <h1>; heading levels nest in order (no skipping).
05Every meaningful image has alt text; decorative ones use alt="".
06Layout is responsive and usable from 320px up to desktop, no horizontal scroll.
07No inline style="" attributes; no !important hacks.
08CSS is commented and grouped into logical sections.

handing in

Submission & self-check

What to submit

  • A single folder named yourname-northstar/ containing index.html and styles.css (plus any image files), zipped.
  • A short README.txt (150–250 words): which stretch goals you attempted and one thing you found hard and how you solved it.

Run this checklist before you submit

  • Opened index.html in a fresh browser and clicked every nav link — they all jump correctly.
  • Resized the window from narrow to wide — nothing overflows or breaks.
  • Tabbed through the page with the keyboard — focus is always visible.
  • Ran the HTML through the W3C validator — zero errors.
  • Searched the HTML for style=" — there are none.
  • Deleted styles.css temporarily — the page still makes sense unstyled (proves clean structure).
Academic honesty

Write your own HTML and CSS. You may consult the two manuals and reference docs, but copying the finished tutorial files, or another student's work, will be treated as plagiarism. The point is the practice, not the pixels.

A tip for a smooth run

Build in the manual's order: get all the HTML done and validating first, viewing it unstyled. Only then start styles.css. Trying to style half-built markup is where most time gets lost.
